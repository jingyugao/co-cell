# 模型过载重试

Sandbox worker 的 Responses 代理对明确的模型容量错误重试当前 HTTP 请求。首次请求失败后依次等待 **10、30、60、180 秒**，最多重试四次，即共五次请求。计时从容量失败确认时开始，首次原通道查询计入第一次等待窗口。

## 触发条件与原通道

仅识别 `server_is_overloaded`、`model_at_capacity`、`model_capacity`：可以来自 HTTP 200 SSE 的 `error` / `response.failed`，或 HTTP 503 JSON。认证失败、普通限流、未完成响应、未知断流和工具执行错误不自动重跑。受控代理 provider 的 Codex HTTP/stream 内置重试设为零，避免与应用重试叠加。

重试先使用失败响应的完整 `x-oneapi-request-id`，向同源 New API 的 `GET /api/log/token` 查询当前 API token 自己的记录，精确匹配唯一原通道。随后仅为该请求构造 New API 支持的通道固定鉴权，保持 API token 身份、模型、正文和会话路由键不变，不修改平台凭据文件或全局通道配置。

解析最多查询三次，每次最多两秒。缺少可匹配记录、通道冲突、权限不足或鉴权格式不支持时，返回真实失败，不猜测通道，也不随机切换。这项能力依赖代理的日志查询和固定通道语义，不适用于任意 Responses 服务。

“原通道”保证的是本应用构造的重试请求。代理服务自身可能在特定异常路径内部重试或切换，行为取决于其实现和版本；本应用没有修改代理集群配置，不能保证其所有内部异常路径都保持通道。

## 工具与流式边界

重试单位是一条模型 HTTP 请求，不是整个 turn，也不重新提交用户任务。此前已完成工具的结果保留在请求正文中。候选响应先缓存在内存，确认成功后再释放给 SDK；失败尝试中的工具调用不下发，避免执行不完整结果或重复触发工具。

因此页面仍展示 SDK 任务与工具事件，但同一次模型响应的文本会在确认完成后释放。不能把这一过程视为逐 token 直通。

请求和响应各最多缓冲 8 MiB。超限时转为直通，并禁止该请求重试；已向下游释放内容的响应也不会重新发送。正文不写入诊断日志。等待时发送 SSE 注释保活；停止任务或关闭代理会取消计时和上游连接。

## 页面、状态与排障

页面展示等待倒计时和重试次数，例如“模型繁忙，10 秒后重试（1/4）”，发出下一次请求后切换为重试中。现有停止按钮同时取消重试等待。

重试状态随会话持久化并通过 SSE 发送，页面刷新后可恢复展示；终结、取消和新轮次清除状态。Web 服务重启会中断任务和等待，不会根据旧倒计时自动重发请求，需要用户继续会话。

运行日志记录次数、间隔、原通道与请求标识。出现 HTTP 200 但任务失败时同时查看 SSE 终止结果；查不到原通道时检查完整请求标识、当前 token 的日志权限及代理兼容性。
