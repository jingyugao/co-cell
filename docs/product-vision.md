# CoCell 产品定位与目标体验

本文定义 CoCell 最终希望成为的产品，作为后续功能取舍、交互设计和验收的依据。文中的能力均为目标要求，不表示当前已经实现。实现与验收进展统一记录在[产品完善进展](product-progress.md)。

本版定位为 AI 研发工作台，不限定个人使用，后续可支持多人协作。自托管作为部署方向，不作为目标用户的限制。尚需讨论的边界列在文末；技术选型、接口和部署方式不在本文展开。

## 1. 一句话定位

**CoCell 是以项目为核心的 AI 研发工作台，通过可复用工作流减少重复操作，统一管理 Agent 任务、Sandbox 资源、项目归档、报告复盘与费用。**

CoCell 是建立在 Codex 等 Agent 执行能力之上的项目应用与工作流。Agent 负责理解指令、分析问题和执行任务；CoCell 负责把这些工作归到项目，管理项目的环境、记录、报告、费用和生命周期。使用者负责目标、关键决策与结果验收。

“CoCell”是统一产品名称；“swarm-hive”仅作为历史名称。

## 2. 为谁服务，解决什么问题

核心用户是使用 AI 推进研发工作的开发者与研发团队，尤其是需要持续维护项目、切换多项任务和复用业务经验的使用者。单人可以独立完成工作；后续多人协作应支持围绕同一项目分工、交接与审阅成果，具体能力分阶段定义。

| 工作中的问题 | 用户希望得到的结果 | CoCell 的价值 |
| --- | --- | --- |
| 同类任务每次都要重新交代步骤、准备资料和检查遗漏 | 保存并重复执行项目工作流 | 减少重复指令和人工调度 |
| 多个项目的 Sandbox 一直运行，闲置时仍占内存 | 暂时不用时暂停，需要时恢复 | 让有限资源优先用于活跃项目 |
| 已结束的项目长期占用环境和磁盘 | 保留可恢复备份，回收原环境 | 保留成果，同时减少闲置环境占用 |
| 日报周报需要人工翻会话、查提交、拼进展 | 自动按项目汇总已完成、进行中、阻塞与下一步 | 减少重复整理工作 |
| 项目结束后难以回顾决策、返工和问题 | 根据项目记录生成可核对的复盘与改进项 | 为后续工作保留具体经验 |
| 模型和环境消耗分散，算不清一个项目的费用 | 按项目归集用量、费用与计费明细 | 知道每个项目花了多少、花在哪里 |
| 每次开始会话都要重新解释业务、仓库和约定 | 新任务能够利用已有背景，先确认变化再推进 | 减少重复说明与重复调查 |
| 多项工作交错，回来时忘记做到哪里 | 快速知道目标、进展、阻塞和下一步 | 降低任务切换与重新接手的成本 |
| 长任务依赖持续盯着窗口 | 离开后继续执行，需要决定时再找人 | 减少等待与人工看守 |
| 不同项目环境准备繁琐，闲置环境持续占资源 | 需要时可用，暂时不用时可回收，回来可接续 | 降低环境维护负担 |
| 工作散落在聊天、代码、需求和文档中 | 从需求到结果都能找到依据与产物 | 提高交付的可检查性 |
| 排障经验停留在一次对话里 | 后续任务能复用可靠经验，并纠正过时内容 | 让长期使用带来持续收益 |
| 换设备后无法跟进正在进行的工作 | 电脑、手机和平板都能接续同一项任务 | 让工作跟随使用者 |
| 工作交接依赖口头说明和复制聊天 | 获授权成员能理解目标、决策、进展和待办并接手 | 降低协作与交接成本 |

### 与 Codex 的分工

Codex 官方当前文档已涵盖多项目、长任务、定时工作、工具连接，以及手机远程跟进。CoCell 不将这些通用能力单独作为差异化依据。参考：[官方功能说明](https://developers.openai.com/codex/app/features)、[Codex Remote](https://developers.openai.com/codex/remote)（查阅于 2026-09-22）。

在 CoCell 的产品分工中，Codex 提供通用 Agent 执行能力，CoCell 提供围绕项目的上层应用工作流。差异体现在日常管理中：哪个项目的环境可以暂停，哪个项目已经归档，本周各项目做了什么，一个项目累计花了多少，以及哪些问题需要在下次避免。

| 差异化方向 | CoCell 应形成的完整体验 |
| --- | --- |
| 可复用工作流 | 保存步骤、输入、产物和人工确认节点，复用项目配置，按次跟踪执行结果与中断恢复 |
| Sandbox 资源管理 | 按项目查看资源占用，暂停闲置环境，需要继续时恢复 |
| 项目归档 | 保存工作区与必要上下文后回收环境；历史记录、报告与账目仍可查询，后续可以恢复工作 |
| 日报周报 | 按周期从项目任务、会话和产物汇总进展，关联来源，供用户检查与补充 |
| 项目复盘 | 汇总目标达成情况、关键决策、返工、阻塞和投入，形成有来源的改进事项 |
| 项目维度计费 | 将任务、会话、模型用量和环境消耗归到项目，提供项目费用汇总与明细 |
| 后续多人协作 | 成员围绕同一项目分工、交接、审阅，共用项目记录并按权限访问资源 |

Agent 可以根据指令写一份周报；CoCell 要负责持续收集属于项目的记录、按约定周期生成报告并保留历史。Agent 可以执行环境操作；CoCell 要负责所有项目环境的状态、回收策略与恢复入口。这些长期管理职责由应用承担，不要求用户每次通过对话重新安排。上述能力均为产品目标，具体实现进展独立跟踪。

## 3. 核心价值与产品原则

项目是资源管理、归档、报告、复盘和计费的共同单位。同一项目中的任务与会话使用同一套项目记录；关闭会话不结束项目，暂停 Sandbox 不归档项目，归档项目不删除报告和账目。资源状态、工作状态和费用状态应分别展示清楚。

### 工作具有连续性

项目目标、任务状态、决策、产物与必要环境共同构成可接续的工作。用户隔天回来或换一台设备，应当能理解当前情况并继续推进。恢复体验需要说明保留了什么、哪些内容需要重新准备。

### 委托具有明确边界

用户可以明确任务目标、完成标准、资源范围和需要确认的操作。Agent 能自主推进已授权工作；遇到信息缺失、失败或关键决策时，给出原因和可选处理方式。用户可以补充指令、暂停、取消或调整方向。

### 交付具有可检查的证据

每个任务都应说明完成了什么、验证了什么、产物在哪里、还存在哪些问题。执行结束和用户验收完成是两个独立状态。失败与中断同样保留有效进展和接续入口。

### 经验能够复用和纠正

长期知识具有来源、适用范围和维护入口。新任务按需要使用相关经验，用户能够检查、修订和停用过时内容，避免错误认识在后续工作中反复传播。

### 日常管理保持轻量

简单任务可以直接开始；复杂任务可以逐步补充方案、步骤与验收标准。资源与费用信息帮助用户做决定，常规使用无需理解底层运行细节。

## 4. 产品中的核心对象

| 对象 | 含义 | 用户如何使用 |
| --- | --- | --- |
| 项目 | 工作、资源、归档、报告和计费的组织单位，关联代码、资料、环境与项目知识 | 查看进展和费用，管理环境，生成报告，复盘与归档 |
| 任务 | 有明确目标、状态、产物与完成标准的工作单元 | 提交需求、修复缺陷、调查问题、安排后续工作 |
| 会话 | 用户与 Agent 讨论、澄清和推进工作的交流上下文 | 讨论方案、补充指令、追问依据；必要时为同一任务展开专题讨论 |
| 工作环境 | 执行任务所需的代码、文件、工具和运行条件 | 启动工作、查看预览、暂停闲置环境、恢复历史工作 |
| 工作产物 | 任务交付的可检查结果 | 查看代码变更、文档、验证记录、报告和交付链接 |
| 知识与工作流 | 可复用的事实、约定、经验和工作步骤 | 让后续任务沿用已确认的背景和处理方法 |
| 待办与通知 | 需要使用者留意、决定或安排的事项 | 处理阻塞、确认结果、接收提醒和跟进改进建议 |
| 项目报告 | 按时间或阶段归集的日报、周报与复盘 | 核对工作进展、回顾问题、跟进改进项 |
| 项目账目 | 归属于项目的模型与环境用量、费用及计费依据 | 查看累计投入，按周期和任务核对明细 |

任务是跟进与验收的基本单位，会话是推进任务的入口。一次对话可以帮助形成任务；多次对话也可以共同推进同一任务。用户应能直接查看任务结论，无需翻阅全部聊天记录。

## 5. 主要功能与目标体验

### F01 项目与任务管理

支持手动输入目标，或从已有需求与缺陷来源引入工作。项目保存背景、关联资料和阶段目标；任务保存完成标准、优先级、进展、阻塞与产物。跨项目总览帮助用户找到正在推进和需要关注的工作。

**完成体验：** 用户打开工作台，就能判断目前在做什么、哪些事项需要自己处理，以及接下来可以推进什么。

### F02 可复用的项目工作流

将需求澄清、方案讨论、开发、验证、交付和项目收尾等重复步骤保存为工作流。定义每一步所需输入、预期产物、执行顺序与人工确认节点；启动时复用项目背景、工具配置和工作约定，只补充本次工作需要的信息。

提供需求分析、开发交付、日报周报和项目收尾等内置模板，支持按项目调整、手动执行或定时执行。每次运行保留采用的工作流版本、输入、步骤状态和产物。失败或中断后可以从合适的步骤继续，重试前明确已经完成的外部操作，避免重复提交或重复发送。

复杂任务支持拆分步骤和并行处理，展示各部分进展与汇总结果；共享工作成果时能够识别和处理冲突。用户可调整目标，关键决策保留依据。工作流执行遵守项目授权，保存模板不自动授予其中外部操作的权限。

**完成体验：** 同类工作再次出现时，用户选择工作流并补充本次输入即可开始，不必重新描述全套步骤；可查看执行到哪一步、有哪些产物，以及失败后如何继续。

### F03 持续执行与人工介入

长任务在用户离开后继续推进。用户回来后可以看到期间发生的变化；遇到待确认事项时，显示问题、目标、影响和可选操作。失败或中断后能够保留有效进展，并提供重试或继续处理的入口。

**完成体验：** 用户不必持续盯着会话窗口，也能掌握关键变化，并在需要时接手。

### F04 Sandbox 资源管理与项目归档

项目环境按需准备，同项目的多个会话复用项目环境，避免每开一个会话就重复准备一套环境。按项目展示 CPU、内存和磁盘占用，支持配置闲置回收策略。

| 项目使用情况 | 目标行为 | 用户收益 |
| --- | --- | --- |
| 正在工作 | 环境运行并保留工作状态 | 可继续执行任务、测试与预览 |
| 暂时闲置 | 保存必要状态后暂停，释放运行内存；活动任务不按闲置处理 | 不必为所有历史项目持续保留运行资源 |
| 项目结束或长期不用 | 备份工作区与必要上下文，确认可恢复后归档并回收原环境 | 减少长期保留环境的磁盘占用 |
| 重新处理历史项目 | 从保存内容恢复环境，说明恢复结果及需要补做的准备 | 无需从头整理代码和历史上下文 |

暂停后的状态文件和归档备份仍占存储空间，产品应展示实际占用、保留版本及回收结果。归档后，项目任务记录、日报周报、复盘和计费明细仍可直接查看；恢复执行环境只在需要继续工作时进行。

**完成体验：** 用户能知道哪些项目正在占用资源、哪些已暂停或归档、实际释放了多少资源，并能恢复指定项目继续工作。

### F05 长期知识与可复用工作流

管理个人通用约定、项目背景、业务规则、关键模块、环境说明、常见问题与操作经验。Agent 在任务中提出知识补充和纠错建议，附带依据；确认后供后续任务复用。支持整理重复、冲突和过时内容，并将稳定步骤沉淀为可复用工作流。

**完成体验：** 同类任务再次出现时，能够利用已有结论和步骤，用户也能追溯并修正其依据。

### F06 研发工具连接与授权

连接代码托管、需求管理、文档、数据查询和运行环境等已有研发工具，使用户能在项目上下文中完成调查与交付。按任务或项目说明可访问的资源、可执行的操作及需要确认的边界；操作结果保留来源与记录。

**完成体验：** Agent 可以使用获准的研发资源，用户清楚它能做什么，并能在关键外部操作前作出决定。

### F07 结果审阅与工作可见性

集中展示任务摘要、代码差异、文档、预览和验证结果，支持进一步查看执行依据。展示耗时、模型消耗与环境资源使用；估算值与实际记录应有明确区分。用户可以验收、提出修改或重新打开任务。

**完成体验：** 用户能够判断结果是否达到目标、是否值得继续投入，并找到支撑判断的证据。

### F08 跨设备接续

电脑承担完整的研发和审阅体验；手机、平板支持查看状态与结果、补充指令、处理确认和接收提醒。各设备使用同一份工作状态，未处理事项保持一致。

**完成体验：** 用户在电脑上发起工作，离开后可以在手机上处理问题，回到电脑后继续验收。

### F09 项目日报周报与定时安排

按项目和指定时间范围，从任务状态、会话结论、代码变更与验证记录中自动汇总日报周报。报告包含已完成事项与产物、进行中事项、阻塞、待决定问题和下一步；费用摘要关联项目账目。跨项目周报按项目分别展示，避免混淆工作归属。

报告关联来源，区分已验证结果、执行中的工作和未确认结论。用户可以修订补充、手动重新生成，也可以设置周期生成并查看历史。记录缺失时明确提示，不将未记录的工作写成已完成。自动生成和对外发送分别设置，生成报告不默认授权发送。

同时支持指定时间提醒、启动已安排的任务和周期性知识整理。用户能够查看、修改、暂停或取消安排，并检查运行结果。自动执行仍遵守既定授权边界。

**完成体验：** 到约定时间，用户能直接查看各项目的日报周报，核对来源、补充遗漏，无需从头翻阅会话整理进展。

### F10 项目复盘与改进跟进

在项目完成或阶段结束时，根据项目目标、产物、任务记录和账目生成复盘草稿：哪些目标已达成、哪些未完成、发生过哪些关键决策、返工和阻塞、投入了多少时间与费用。涉及原因判断时区分记录事实与待确认分析，支持用户补充背景。

从复盘中提取可复用经验和具体改进项，关联原始记录。改进项支持暂缓、转为后续任务和记录处理结果；确认后的经验写入项目知识。执行期间也可以随时收集代码、业务流程、知识和环境改进建议。

**完成体验：** 项目结束后，可以查看成果、问题与投入，找到支撑结论的记录，并把改进事项落实到后续任务。

### F11 项目维度计费

将模型调用、Agent 执行及 Sandbox 的资源用量归集到所属项目。展示项目累计费用、周期费用，以及按任务、会话和费用类型展开的明细；多人协作后可按成员查看归属。归档项目仍保留账目，恢复后的新增费用继续归到原项目。

计费明细应说明用量、单价或计费规则与统计时间范围。模型费用、运行资源费用、归档存储费用分开呈现；暂停环境与归档不表示所有费用归零。估算费用、外部实际账单与平台收取的费用分别标注，缺失费用不当作零费用，共享资源的分摊规则需要明确。

本版将“项目维度计费”先定义为项目用量计量、费用归集和账单展示。是否对外收费、如何结算、是否支持预算和额度控制，需要另行确定，本文不预设价格或支付方案。

**完成体验：** 用户能回答“这个项目总共花了多少、主要花在哪里”，并沿项目账单查到费用依据。

## 6. 三个完整使用场景

### 场景一：推进一个研发需求

用户创建项目或引入需求，说明目标与完成标准。Agent 结合项目知识和相关代码梳理问题，提出方案。用户确认关键取舍后，Agent 推进开发与验证，在需要时请求介入。用户通过差异、预览和验证记录验收，结果关联回原始任务；可复用经验进入知识维护流程。

### 场景二：多个项目交错推进，每周查看汇总

用户同时维护多个项目，只有正在工作的项目保持环境运行，其余闲置项目暂停以释放内存。任务执行期间可以离开电脑，在手机上查看进度或处理待确认事项。到周末，CoCell 按项目汇总已完成事项、阻塞、下一步和本周费用，用户核对后形成周报。

### 场景三：项目复盘、归档与重新启用

项目完成后，CoCell 汇总交付成果、主要问题、返工与累计费用，生成复盘草稿。用户确认结论和改进项后归档项目，回收原环境。几周后需要修复问题时，用户先查看历史复盘和任务记录，再恢复环境继续工作；新任务和费用继续归属于该项目。

## 7. 产品边界

产品支持单人使用，并为后续多人协作保留明确的发展方向。跨设备接续与多人协作分别定义：前者解决访问与跟进，后者需要补齐成员、分工、共享、权限、审阅与交接体验。多人协作的具体范围与交付阶段尚未确定，不代表当前已可用。

自托管是产品的部署方向。组织治理、多租户商业化和公开市场不在本版展开；支持多人协作并不自动引入这些范围。

CoCell 连接已有代码托管、需求管理和研发工具，保留其作为业务记录来源的职责。编辑、终端和预览能力服务于任务完成与验收；完整通用 IDE、通用项目管理系统和基础设施管理平台不属于本版范围。

开发者始终拥有目标、授权和验收的决定权。产品需要明确呈现不确定性、失败与待验证结果，不以“Agent 已结束”代替交付达标。

## 8. 如何判断产品产生了价值

本阶段先确定观察方向，具体统计口径与目标值在体验方案明确后补充。

| 价值方向 | 应关注的表现 |
| --- | --- |
| 闲置资源减少 | 暂停前后的运行内存占用，以及归档回收与保留备份各占多少磁盘空间 |
| 报告整理省时 | 日报周报能自动覆盖有记录的项目进展，来源可核对，减少人工搜集与整理 |
| 复盘能用于后续工作 | 项目问题有依据，改进项有后续任务，经验在后续工作中得到复用 |
| 项目费用可核对 | 用量和费用有归属、有依据，能区分实际值、估算值与缺失项 |
| 更快进入有效工作 | 新任务和历史任务接续时，重复介绍背景、查找资料和准备环境的负担下降 |
| 减少人工看守 | 长任务能够持续推进，人工介入集中在必要决策和验收 |
| 交付更易确认 | 用户能找到产物与验证依据，清楚完成与未完成的范围 |
| 知识确实可复用 | 后续任务能用到已确认经验，过时或错误内容能够被发现与修正 |
| 工作连续性更好 | 跨设备、跨时间与恢复环境后，用户仍能理解状态并继续工作 |
| 投入可掌握 | 用户能理解任务的时间、模型与环境消耗，并据此调整安排 |

## 9. 后续需要明确的产品问题

- 项目如何支持长期产品维护与短期需求工作：任务如何归属、跨项目资料如何关联。
- 任务、会话和工作流在界面中如何组织：简单工作需要多少必填信息，复杂工作何时展开更多管理能力。
- 自动整理知识的确认方式：哪些内容只能建议，哪些可按用户规则直接维护，如何追溯与撤销。
- 定时能力的使用边界：提醒与自动执行如何区分，错过执行时间或资源不可用时如何处理。
- 移动端首批完整场景：哪些审阅与确认必须能独立完成，哪些需要回到电脑。
- 多人协作的首批场景：成员如何分工、接手任务和审阅结果，项目知识、工作环境与操作权限如何共享或隔离。
- 项目计费范围：资源费用如何计算和分摊，是否包含对外收费与结算，是否需要预算控制。
- 日报周报与复盘：默认模板、生成时间、人工修订后的更新方式，以及记录不足时如何标注。
- 资源管理与归档：闲置判断、备份保留规则、可恢复内容与实际回收结果如何呈现。

上述问题不妨碍定位成立，但需在相应功能进入设计前形成明确结论，并在进展文件中跟踪。
