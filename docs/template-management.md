# 模板管理

通过侧栏“模板管理”或 `/#templates` 管理本应用的 E2B 开发环境配置。这里展示本应用保存的配置和构建历史，不是 E2B 账户下全部外部模板的库存。

## 前置条件

页面构建和 `pnpm e2b:build` 都依赖已安装的本机客户端：

```text
~/.data/e2b/client/config.mjs
```

该模块不随仓库提供，须导出异步 `localConfig()` 和 `requireHealthyApi(config)`。前者返回已认证的 E2B SDK 连接配置，后者检查 API 可用性。Web 运行时的环境变量连接与构建客户端配置应指向同一个 E2B 部署，否则构建产物可能无法用于项目沙箱。

部署需要具备构建权限、可用基础镜像、足够磁盘、内存和大页资源。构建前先检查部署额度；调整额度不会直接扩大已有沙箱的磁盘。

## 页面操作

1. 新建配置或复制已有配置，填写名称、安装版本和工具。
2. 保存配置。Go、Node、Python 的默认版本必须在各自安装列表中。
3. 点击“构建并验证”。后台构建模板，再创建临时沙箱检查版本、编译与运行环境，结束后清理验证沙箱。
4. 验证通过后点击“设为新沙箱默认”。无需重启 Web，只影响此后创建的沙箱，已有项目沙箱和文件保留。

配置使用固定完整版本。Go 和 Node 通过 mise 管理，Python 使用 uv；不同项目目录可选择不同版本。PHP 是可选的原生 CLI 环境，当前支持 PHP 8.0.30 与 Composer，不需要在沙箱内运行 Docker。Codex SDK 的控制 Node 与项目 Node 版本分离。

系统工具填写 apt 包名；额外 mise 工具使用 `tool@version`。Codex SDK 版本跟随 Web 服务。mise、uv 和 Composer 的安装包使用清单中的校验值。模板只安装工具，不包含本机凭据、共享文档或项目代码。

保存、构建和切换默认是三个独立操作。构建使用当时保存的清单快照和独立 E2B 别名，后续编辑不会改变该构建。页面一次只执行一个构建，可离开页面后回来查看进度；重启服务会中断本机构建任务，不能当作后台守护运行。

删除配置只删除本应用的配置及本地构建记录，不删除远端模板或项目沙箱。包含当前默认版本或正在构建的配置不能删除。保存和删除校验版本，编辑冲突时保留页面草稿。

## 命令行与存储

仓库清单 `scripts/e2b/toolchains.json` 供命令行构建使用：

```sh
pnpm e2b:build
```

命令依次运行模板构建和临时沙箱验证，报告写入 `data/e2b/`。它不会自动更改页面管理的默认模板；命令行清单和页面配置在首次导入后独立维护。

页面状态位于 `data/e2b/templates/state.json`，各构建快照及报告位于 `data/e2b/templates/jobs/`。首次初始化导入仓库清单，并仅在已有报告与清单匹配且验证成功时导入对应结果。`E2B_TEMPLATE` 仅作为首次初始化默认值，之后以持久化的页面默认值为准。

构建脚本使用 `fromBaseImage()`，让部署按当前额度准备磁盘；复用旧模板会继承旧磁盘。安装脚本与清单通过 RUN 写入以兼容本机 builder，不依赖其文件上传层。新增通用工具优先修改清单，特殊安装流程再调整对应 `scripts/e2b/` 安装脚本。

服务正常关闭会终止本机构建子进程，验证脚本尝试清理临时沙箱；异常退出后的未完成记录在重启时标为中断。已提交的 E2B 远端构建可能仍继续，但本应用不会自动将其启用为默认。
