# CoCell

**以项目为核心的 AI 研发工作台：用工作流减少重复操作，管理 Sandbox 资源、项目归档、日报周报、复盘与费用。**

一个项目的工作往往分散在多次 Agent 会话中：需求分析、代码开发、问题排查、验证和交付。CoCell 把这些工作放回同一个项目，复用环境和知识，记录产物与消耗，并处理项目闲置、结束和重新启用时的管理工作。

> 以下介绍目标产品的主要能力，不代表当前版本已全部实现。具体进展单独记录在[产品完善进展](docs/product-progress.md)，当前运行方式见[快速开始](#快速开始)。

## 以项目组织工作

项目是 CoCell 管理工作、资源和费用的基本单位。打开一个项目，应当能找到：

- **目标与任务**：要做什么、进展如何、有哪些阻塞和待确认事项。
- **会话与工作流**：每次讨论和执行的记录，以及可以重复使用的工作步骤。
- **Sandbox 与工作区**：项目代码、文件、工具和运行环境，以及当前资源占用。
- **产物与知识**：代码变更、验证结果、业务说明、历史决策和操作经验。
- **报告与账目**：日报周报、项目复盘、累计费用和用量明细。

关闭一次会话后，项目记录继续保留；暂停 Sandbox 后，仍可查看进展；项目归档后，报告、复盘和账目仍可查询。后续多人协作也围绕项目展开，支持成员分工、交接、审阅和按权限访问资源。

## 核心能力

### 1. 复用工作流，减少重复操作

将经常重复的研发步骤保存为工作流，复用项目背景、工具配置和工作约定。每次执行时提供本次需求，按步骤推进，在需要判断的节点交由人确认。

| 工作流 | 典型步骤 |
| --- | --- |
| 需求分析 | 读取需求与项目知识 → 查阅相关代码 → 输出方案与待确认问题 |
| 开发交付 | 执行开发任务 → 运行检查 → 整理变更与验证结果 → 按授权创建 MR |
| 日报周报 | 收集项目记录 → 汇总成果、阻塞与费用 → 生成报告 |
| 项目收尾 | 汇总交付 → 生成复盘 → 提取经验与改进项 → 确认后归档 |

工作流支持手动或定时执行，保留每一步的进度、产物和失败原因。中断后能选择合适的步骤继续，避免重复已经完成的工作。日报周报和项目收尾可以使用内置模板，再按项目需要调整。

### 2. 按需运行 Sandbox，节省资源

同一项目中的会话复用项目环境，减少重复安装依赖和准备代码的工作。多个项目交错推进时，根据使用情况管理环境：

| 场景 | 处理方式 | 收益 |
| --- | --- | --- |
| 项目正在工作 | 按需启动，持续运行任务 | 保留开发、测试和预览环境 |
| 暂时闲置 | 保存必要状态后暂停，需要时恢复 | 释放闲置环境的运行内存 |
| 项目结束或长期不用 | 备份后归档，回收原环境 | 减少长期保留环境的磁盘占用 |

按项目查看 CPU、内存和磁盘占用，配置闲置回收策略，了解哪些环境仍在运行、实际释放了多少资源。正在执行任务的环境不应按闲置回收。

### 3. 项目归档后，仍可恢复工作

项目告一段落后，保存工作区与必要上下文，再回收原 Sandbox。项目记录、产物、报告和费用随项目保留，查阅历史资料无需先恢复执行环境。

需要继续开发或修复问题时，从备份恢复工作环境，接续已有代码和上下文。恢复结果应说明哪些内容已恢复、哪些准备需要重做。

备份和暂停状态文件仍占存储空间。项目应展示保留版本、存储占用和回收结果，方便用户决定保留多久。

### 4. 自动汇总项目日报、周报

按项目和时间范围，从任务、会话结论、代码变更和验证记录中汇总：

- 已完成的工作与对应产物。
- 进行中的事项、阻塞和需要决定的问题。
- 下一步计划与本周期费用。

支持定时生成、手动生成和人工补充，跨项目周报按项目分别汇总。报告关联原始记录，区分已完成、进行中与待验证事项，减少翻会话、查提交和拼进展的工作。

### 5. 项目复盘，把问题和经验留下来

项目完成或阶段结束时，汇总目标达成情况、关键决策、返工、阻塞和时间费用投入，生成可核对的复盘草稿。

确认后的业务知识和操作经验进入知识库；需要改进的事项可以转为后续任务，继续跟进处理结果。下一次处理类似需求或问题时，复用已有经验，减少重复调查与踩坑。

### 6. 按项目计费，看清投入

将各任务和会话的模型用量，以及 Sandbox 运行和归档存储的消耗归到项目，展示累计费用、周期费用和明细。

用户可以查看“这个项目花了多少、主要花在哪里”，进一步按任务、会话和费用类型核对计费依据。项目归档后保留历史账目，恢复后的新增费用继续归到原项目。

估算费用与实际账单分别标注。具体计费规则、共享资源分摊及是否提供收费结算，在后续产品设计中明确。

## CoCell 与 Codex 的分工

CoCell 是建立在 Agent 执行能力之上的项目应用与工作流。当前使用 Codex App Server 执行 Agent 任务。

在这个分工中，Agent 负责分析需求、阅读代码、执行命令和生成成果；CoCell 负责项目归属、工作流安排、环境管理、报告记录和费用归集。

例如，Agent 可以根据指令生成一份周报；CoCell 负责收集项目记录、按周期发起生成、关联成果与费用，并保存每一期报告。项目结束后，CoCell 继续管理归档、备份和账目，直到需要重新启用。

## 一个项目如何使用 CoCell

1. **创建项目**：填写目标或关联需求，准备项目知识与工具配置。
2. **选择工作流**：复用需求分析、开发交付等步骤，补充本次任务要求。
3. **执行与检查**：Agent 在项目 Sandbox 中工作，用户查看进度、处理确认并检查产物。
4. **日常跟进**：自动汇总日报周报，查看费用；暂时闲置的环境暂停以释放资源。
5. **复盘与归档**：汇总成果、问题和投入，确认经验与改进项，备份后回收环境。
6. **重新启用**：查阅历史记录，按需恢复环境，新任务与费用继续归到原项目。

## 当前版本与进展

当前版本面向可信用户自托管、单用户使用。已有项目与会话、项目 Sandbox、备份归档、共享知识与改进建议等基础能力，当前用法见各模块文档。

可复用工作流、自动日报周报、项目复盘和完整项目计费属于目标范围，覆盖度与验收状态在[产品完善进展](docs/product-progress.md)单独跟进。现有会话 Token 与费用估算不等于完整项目账单，多人协作为后续方向。

## 快速开始

开发环境需要 Node.js 22.18+、pnpm 10、Docker，以及可用的模型认证和 API 入口。执行 Agent 任务还需准备包含 Node.js 和 Codex CLI 的 CellBox 镜像；使用 gVisor 时还需配置 runsc、CNI 和 helper。

在仓库根目录执行：

```sh
pnpm install --frozen-lockfile
test -f .env || cp .env.example .env
mkdir -p data/docs
touch data/AGENTS.md
```

按照[开发运行与数据维护](docs/development-and-operations.md)填写模型认证、Sandbox 镜像与运行环境配置，然后启动 Web 开发服务：

```sh
PORT=3001 pnpm dev
```

打开 <http://localhost:3001>。Web 服务启动后，执行任务仍依赖 Sandbox 环境配置完整。配置变量、镜像准备、gVisor helper、Compose 使用条件和备份目录统一见运行文档。
