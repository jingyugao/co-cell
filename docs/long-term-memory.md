# 长期记忆

长期记忆用于沉淀项目背景、业务规则和研发经验，让新会话可以复用已有认识，减少重复解释与调查。CoCell 采用文件化共享知识、持久化会话和改进建议相结合的维护方式。

## 知识放在哪里

| 位置 | 内容 | 维护方式 |
| --- | --- | --- |
| `data/AGENTS.md` | 工作约定、协作流程和任务要求 | 在共享文件页面编辑 |
| `data/docs/` | 项目介绍、业务模块、常见问题和操作经验 | 在共享文件页面编辑，可分目录组织 |
| 项目会话及 Sandbox 的 `~/.codex` | 对话过程与原生 thread 状态 | 执行任务时保存，随项目数据备份 |
| `data/improvements.sqlite` | Agent 提出的改进建议及处理记录 | 在建议页面查看、筛选和更新状态 |

仓库中的 `docs/` 用于说明 CoCell 自身；`data/docs/` 是使用者维护并提供给业务 Agent 的知识库。根目录 `AGENTS.md` 是贡献指南入口，运行任务的共享约定由 `data/AGENTS.md` 提供。

## 如何在任务中复用

每轮任务准备时读取共享知识，包括继续已有 thread 的任务。`data/docs/` 同步到 Sandbox 的 `/home/user/.codex/docs/`，共享规则挂载到 `/home/user/.codex/AGENTS.md`。

建议在知识库中维护：

- `README.md`：知识目录和阅读入口。
- `project-overview.md`：各仓库职责、业务边界与跨仓库关系。
- `key-modules.md`：关键模块、业务规则、流程和上下游依赖。
- 专题文档：经验证的排障方法、设计决策和操作经验。

任务按需查阅这些文档，结合实际代码判断其适用范围。共享内容不需要在每个项目内重复维护。

## 从任务经验到长期知识

1. Agent 在工作中发现有价值的缺失、错误或过时信息。
2. 使用 `submit_optimization` 提交知识库或环境优化建议，包含事实依据、目标文件、章节和可收录的正文；一般改进机会可使用 `submit_improvement_proposal`。
3. 使用者在建议页面查看来源项目与会话，判断内容是否可靠、可复用。
4. 将确认后的内容写入共享知识库，并记录建议的处理结果。
5. 后续任务准备时同步更新后的知识。

建议支持“待处理”“暂不处理”“已完成”状态，以及搜索、分类和项目筛选。提交建议保存的是待处理记录；知识内容通过共享文件编辑维护。

## 内容维护

优先记录稳定且可验证的知识，注明依据与适用范围。业务规则变化时更新已有条目，避免保留互相矛盾的说明。凭据保存在连接配置中，日志、抓包和临时调查产物按各自用途单独管理。

共享文本编辑带版本校验，避免旧页面覆盖新内容。共享规则和知识库独立于项目 Sandbox 保存，应连同建议数据库单独备份。
